## Project status

This repo is currently the **unmodified Astro + Cloudflare blog starter template** (site title "Astro Blog", placeholder blog posts, generic header/footer). The real target site is **"Dàn Giáo Hà Nội"** — a Hanoi scaffolding/construction-equipment sales & rental business (site copy in Vietnamese, hotline 0989.776.144, address 82 Đê La Thành, Đống Đa, Hà Nội).

`src/template/index.html` (untracked) is a **static HTML design mockup** for the real homepage — generated by an AI design tool, using Tailwind CDN + a custom design-token config (colors, spacing, fontSize scales defined inline in a `<script id="tailwind-config">` block) and placeholder `lh3.googleusercontent.com` images. It is a reference for the visual design only, not wired into the Astro app. When building out the real site, this mockup's structure/copy/design tokens should be ported into proper `.astro` components (e.g. replacing `src/pages/index.astro`, `Header.astro`, `Footer.astro`), not served as-is. Tailwind is **not** currently an installed Astro integration — the mockup pulls it from a CDN, so wiring it up would need `@astrojs/tailwind` (or equivalent) added properly to `astro.config.mjs`.

## Commands

```bash
npm install                # install dependencies
npm run dev                 # local dev server at localhost:4321
npm run build                # production build to ./dist/ (astro build)
npm run preview              # build, then run via wrangler dev (closest to prod Workers runtime)
npm run check                 # astro build && tsc && wrangler deploy --dry-run — full pre-deploy validation
npm run astro -- --help        # Astro CLI help (e.g. `npm run astro check` for type/content checks)
npm run cf-typegen              # regenerate worker-configuration.d.ts (Env types) from wrangler.json bindings
npm run deploy                   # wrangler deploy — publishes to Cloudflare Workers
```

There is no test runner configured in this repo. `npm run check` (build + `tsc` + dry-run deploy) is the closest thing to a CI gate — run it before considering non-trivial changes done.

## Architecture

- **Framework**: Astro 5, deployed as a Cloudflare Worker (not Pages) via `@astrojs/cloudflare` adapter, serving static assets from `./dist` with the `ASSETS` binding (see `wrangler.json`). `astro.config.mjs` enables `platformProxy` so `Astro.locals` gets Cloudflare runtime bindings (`env.d.ts` types `App.Locals` from the Cloudflare `Runtime<Env>`).
- **Routing**: file-based under `src/pages/`. `src/pages/blog/[...slug].astro` renders individual posts; `src/pages/blog/index.astro` lists them; `src/pages/rss.xml.js` builds the RSS feed from the same collection.
- **Content collections**: blog posts live as Markdown/MDX in `src/content/blog/`, loaded via `astro/loaders` `glob()` and schema-validated in `src/content.config.ts` (`title`, `description`, `pubDate`, `updatedDate?`, `heroImage?`). Add a post by dropping a `.md`/`.mdx` file in that directory — no registration needed elsewhere.
- **Layout**: `src/layouts/BlogPost.astro` wraps post content (hero image, title, dates, prose column) and is the only layout; page-level `.astro` files under `src/pages/` compose `BaseHead` + `Header` + `Footer` directly rather than sharing a common page layout.
- **Site-wide config**: `SITE_TITLE`/`SITE_DESCRIPTION` in `src/consts.ts`, and the canonical `site` URL in `astro.config.mjs` — both are placeholder values (`https://example.com`, "Astro Blog") that need updating for the real deployment.
- **Styling**: no CSS framework wired into Astro currently; `src/styles/global.css` plus scoped `<style>` blocks per component/page is the existing pattern. The design mockup in `src/template/` uses Tailwind (CDN) and a distinct custom design-token naming scheme (`surface`, `surface-container-*`, `on-primary`, etc., following a Material Design 3–style token system) — not currently reflected anywhere in the live Astro styles.
